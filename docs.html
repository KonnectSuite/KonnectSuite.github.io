Get running

Install it, then decide what it may touch

AryaAI is a Windows desktop application. It carries its own Node and Python, so its engineering servers work without you installing a toolchain — with one exception, FactoryTalk Optix Tools, which uses the service of an Optix Studio already on the PC.

Install

Download and run

  1. Download the latest Windows installer from the AryaAI releases page.
  2. Run it. The installer is unsigned, so Windows may ask you to confirm it. Check the file came from the releases page above before you agree.
  3. When it finishes, AryaAI reopens on its own. Chats and settings stay.

The installer is not code-signed yet A SmartScreen prompt is expected, not a sign that something is wrong. Verify the download against the releases page rather than clicking through a prompt from anywhere else.

Operating system
Windows desktop. Seven of the eight engineering servers run on the Node and Python that AryaAI ships with, so they need no separate install; FactoryTalk Optix Tools uses Optix Studio’s own service on this PC.
Shell
The agent’s shell on Windows is PowerShell.
Current version
0.8.0, on DeepSeek Harness 0.2.0-rc.2. Every build is listed on the releases page.
License
MIT. Third-party dependencies are disclosed in THIRD_PARTY_NOTICES.md.

Preview release — read before you install

  • The two vendor engineering bundles are proven in field use. The Studio 5000 L5X and MotionWorks IEC paths have done real engineering work on real machines — the MotionWorks path commissioned a production line end to end — and everything else in the installer is untested against real production work. Read every tool’s boundary before you rely on it for anything.
  • What that proof is, and what is still missing. Proven here means an engineer brought the tool a real problem on a real machine and it answered safely. What the two bundles do not have yet is a trial by an engineer outside the project, written down where a reader can repeat it — that is the first milestone, and it is what the preview label is waiting on.
  • What the field use covers. The MotionWorks IEC path runs offline against staged projects: staging, editing through the IDE’s own APIs, Build and Make, and verification that a change survived a close and reopen. The Studio 5000 path runs offline and online, by two routes — the export-only route that needs no Logix Designer SDK at all, and the SDK route that opens an .acd, builds it offline, and reaches a controller for mode reads, uploads and mode changes.
  • Installing an unsigned build to write PLC programs or HMI screens is done at your own risk. The installer is not code signed.
  • While online with a controller, AryaAI is read only. Reading live tag values, the controller mode and diagnostics is what it does by default. Editing online, forcing or toggling a bit, and writing tag or runtime data are refused permanently, and no request from you authorizes them.
  • Three controller actions each ask you first. Uploading the controller into a new local file, changing the controller mode, and downloading raise their own approval prompt naming the controller, the resolved FactoryTalk Linx route, and the exact file and its hash. One approval covers one operation, and the model cannot approve itself.
  • Everything else is an offline file — Studio 5000 work against an exported .l5x or an offline copy of an .acd, and each other tool bounded the same way.
  • The first milestone is Version 1.0 — when the whole line, not just the two proven bundles, carries the evidence to drop the preview label.

First run

Four things worth doing before you trust it with a plant

1. Open a workspace

Point it at the folder your project already lives in, or use a No Repo chat for a question with no folder attached.

2. Turn on only what you need

Windows Computer Use and ComfyUI MCP start with the app; the other engineering servers stay off until you enable them, so a tool you do not have on this machine never blocks startup.

3. Leave the kill switch on

Windows Computer Use can see a window, read its UI Automation tree and OCR the screen without clicking anything. Keep mutating automation refused until you have a reason not to.

4. Add your shop standard as a skill

Naming, alarm text, the cam library, the HMI face. A skill is loaded when it applies, rather than pasted into every chat.

For developers

Run the same UI from source

The web UI is how the product is tested; the desktop window is what ships. Both load the same plugin list.

PowerShell 
# From a development checkout
pnpm install
pnpm run build

# Serve the same UI the desktop window uses, at http://127.0.0.1:3080
pnpm dsh web

The development checkout is not published at a public URL yet These commands apply to a checkout you already have. The Windows installer above is the supported way to run AryaAI today.

The Windows installer is built from apps/desktop. Review SAFETY.md before running a checkout — the harness underneath is in developer preview and keeps changing.

Updates and plugins

What an update does, and what it leaves alone

An update

  • Replaces the application
  • Offers itself from Check for Updates
  • Shows installer progress, then starts again

An update does not touch

  • Your chats
  • Your settings
  • Plugins you added yourself

Uninstalling removes the application, not your workspace It does not delete the Harness home where sessions and plugins live. Install plugins from Settings → Plugin Market, a package name, a Git repository, or a folder on this PC.

Safety model

The principles that do not change

Reading a project and changing a running controller are different acts

Nothing here downloads to a controller. Going online and downloading are planned as their own plugins, with their own confirmation against a named controller, and a backup of what is in the controller comes before a download.

A tool that cannot see its target says so, and AryaAI still starts

A missing factory tool reports itself in the MCP panel. It does not block the application from opening, and it does not silently pretend to be available.

A writer that can destroy a program and report success does not ship

A writer for the MotionWorks IEC project file format was tried and withdrawn for exactly this reason — it could replace a real program body with an empty one and report success. The shipped path is deliberately different: a skill that drives the running IDE and compiles the result, so the compiler is the evidence rather than the writer’s own claim.

The desktop kill switch refuses mutating automation

Mouse, keyboard, element clicks and shortcuts are refused while the kill switch is on, so the agent can look at a window and cannot act on it. Read-only inspection — screenshots, OCR and the element tree — keeps working. Face recognition and the keylogger are not enabled.

If it can be a plugin, it is a plugin

The desktop window and the web UI load the same list. Disabling a row removes that capability on the next start without rebuilding the shell.

Stated plainly

What AryaAI does not do yet

An agent that overstates what it can reach is dangerous in a plant. This section is part of the product, not a disclaimer bolted onto it.

Published limits
Area The limit
Logix Reads a live controller for its mode, tag values and diagnostics. Upload, mode change and download each require their own per-call approval against a named controller. Online edits, forces, bit toggles and data writes are refused permanently. An SDK build needs revision 37 or later, and a download is reachable only from a build verified in the same session with the controller already in Program mode.
Motion Editing goes through the running MotionWorks IEC 3 Pro IDE on a staged copy, not the project file. The file-format writer was tried and withdrawn and is not a starting point. It never downloads to a controller and never commands motion. Ladder and function-block editing and library work are guided workflows still awaiting broader live acceptance.
HMI Does not edit a FactoryTalk View application. FactoryTalk Optix is a different product, and the Optix row talks to Optix Studio only when you turn it on.
Desktop Does not drive the mouse or keyboard while the Windows Computer Use kill switch is on, which is how it ships. Read-only inspection still runs. Turning the kill switch off means real clicks on this desktop.
Desktop driver The experimental Cua desktop driver is in the source tree and is not mounted. Windows Computer Use is the shipped desktop path.
Drawings Does not convert DWG. The drawing you open from the file tree is a DXF.
Ignition The shipped Ignition copy does not talk to a live gateway and does not write tags.

A milestone is finished when the limit is written down Not when the feature demos. What is still open: broader live acceptance for MotionWorks ladder and function-block editing, an SDK build path for controller revisions below 37, and a controller download exercised on real hardware.

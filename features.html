The companion

One agent, pointed at the work you already have

AryaAI is a desktop application, because the engineering tools live on the PC in front of you. A chat in a browser is how the product is tested; the installed application is what a plant PC runs.

Working

Where the agent lives

A workspace folder
The agent plans and edits inside a folder you choose. On Windows its shell is PowerShell, and it reads the same files you do.
No Repo chat
When there is no folder yet — a question about a snippet, a quick lookup — you get a chat with no project attached.
A plan you can open
The agent keeps its plan in the workspace, and you can open that plan beside the chat instead of guessing what it is about to do.
Background jobs
Long work runs as a tracked job rather than blocking the conversation. You are told when it finishes.
Goals that survive the turn
A longer objective keeps the session working across rounds instead of stopping the moment one answer is produced.

Files and drawings

The print stays next to the conversation

A DXF that behaves like a drawing

Open a sheet from the file tree and it renders as a drawing. Scroll to zoom, drag to pan. The agent can list the sheets in an ASCII DXF, read the drawing, and apply an edit that the drawing service checks before it is written.

Checked before write

GitHub, from Settings

Sign in once. From Add workspace you can clone a repository onto this PC and open it. The token stays in your credential store rather than in a project file.

A file tree you already understand

Files open in the pane they belong to, with a sidebar tree rooted where your workspace is. Nothing is imported into a proprietary format first.

Export and diff, not silent edits

Edits to exports and drawings are meant to prove their result — a new file or a reviewed diff, with the tool able to show that what it claims to have written is what is on disk.

Milestone in progress

Images

Generation in the application, and an agent that can drive the graph

The Images page generates against the ComfyUI you already run. The ComfyUI MCP server gives the agent the workflow operations. They are two halves of the same feature, and the WebUI and the desktop window share both.

The Images page
Describe an image, choose a saved workflow, and set size, steps, prompt strength, seed and how many to make. It discovers the checkpoint and Z-Image Turbo models you have installed and checks a workflow against them before running it.
Run history and outputs
Each generation keeps its prompt, workflow, dimensions, steps and seed, and can be reused, downloaded or deleted. Queued and running work can be cancelled.
The ComfyUI MCP server
Comfy Org’s own ComfyUI MCP server, shipped with the comfy-cli engine it invokes. This is the half the agent uses to work on the workflow itself.
Where the browser is kept out
Page code never contacts ComfyUI directly — the application does. That is why the feature works in the desktop window and the WebUI without CORS configuration.
Updates
Ships and updates with AryaAI releases. It never replaces itself from npm.

What the Images page does not cover yet Saved-workflow support is the text-to-image node set, so ControlNet, LoRA, video, custom nodes and three-dimensional graphs stay visible in ComfyUI but unavailable from the page. Gallery entries over 50 MB are refused, deleting an entry clears ComfyUI history but leaves the generated file in ComfyUI’s output folder, and one ComfyUI endpoint is configured per install — changing servers means setting ARYAAI_COMFYUI_URL and restarting.

Teaching it your shop

Skills, workflows, and plugins

A shop standard — naming, alarm text, the cam library, the HMI face — should be something the agent loads, not a paragraph someone pastes into every chat.

Skills

Add a skill that states when it applies and what it should do. It is loaded when the situation matches, so the same behaviour lands on every engineer’s PC.

Workflows

A workflow can run several agents on one job — fan the work out, collect structured results, and keep the intermediate output where you can read it.

Plugins and the Plugin Market

Install more from Settings → Plugin Market, or from a package name, a Git repository, or a folder on this PC. They live in your profile, under your Harness home — not inside the application directory.

An update adds what we ship. It does not take what you installed. The next installer replaces AryaAI. It does not remove your plugins, your chats, or your settings. If a plugin cannot load on a newer AryaAI, the files are still in your profile.

The companion herself

Arya is a pet you can pick up

Arya renders as a sprite-atlas pet in both the desktop workspace and the WebUI. She is a draggable overlay rather than a decoration in a corner, and her pose follows the live conversation — idle, waiting, running or in review — so you can read the agent’s state without reading the transcript.

  • Drag her anywhere — the overlay moves where you put it
  • She looks back — her gaze tracks the pointer
  • Wave on hover, jump on double-click, with a progress bubble while a turn is running
  • Registry-driven — pets are entries in an atlas registry, and a settings section edits the display config in place
  • prefers-reduced-motion swaps in a still, and no two instances animate at once
thinking

Her pose follows the agent: reading the project is researching, drafting a routine is writing, a check is testing, and a finished job is success.

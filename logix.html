Home / Engineering desk / Studio 5000 and Logix

For the Studio 5000 engineer

Edits the project offline. Asks before it touches the controller.

AryaAI reads a Logix export or an offline .acd, draws the ladder in a viewer built into the application, changes the project and proves the build through the Logix Designer SDK. It can also read a running controller — and the three actions that change one are separate tools, each asking you first.

This is the page for the engineer who would otherwise be waiting on a vendor support licence and a ticket queue to find out what a rung does. The tools are field tested and working; the limits below are real, and they are written down rather than left to discover on a running line.

The controller boundary — read this before you point it at a machine

  • Reading a controller is read only. Its mode, live tag values and diagnostics come back as observations, and the tool says so in every answer. No live write of any kind.
  • Uploading the controller, changing its mode, and downloading are three separate tools, and each one raises its own approval prompt. The prompt names the controller, the resolved FactoryTalk Linx route, the exact file and its hash, and the exact change. No tool schema carries an approval flag, so the model cannot approve itself; one approval covers one operation; and the plugin refuses the action outright when the approval service is unavailable.
  • Editing online, forcing, toggling a bit and writing runtime data are refused permanently. No request from you authorizes them through this plugin.
  • A download has never been exercised on a real controller. Upload and mode change have. The download path is written and gated; it is the one part of this integration that is not yet proven, and it says so.

This integration is proven in field use The Studio 5000 path has done real engineering work, offline and online, by two routes: the export-only route that needs no Logix Designer SDK at all, and the SDK route that opens an .acd, builds it offline, and reaches a controller for mode reads, uploads and mode changes. Upload and mode change have run against bench hardware. A download has not — that gap is stated above rather than left for you to discover.

The whole picture, up front

Two halves, and they do not blur

Offline work is where everything happens. The controller is a separate reach with its own confirmations, and it is never implied by “edit the project.”

Offline — a file you review, and a build that proves it

Point it at an exported .l5x or an offline copy of an .acd. You get the controller summary, tags, UDTs, add-on instructions, modules, programs and routines, with cross-references and static checks. An edit is written as a new file beside the source, never over it, and the SDK then imports that file into a fresh offline .acd and builds it.

A build returns its own verdict: the failing stage, parsed import warnings and errors, a log tail, the change summary, and any blockers. A successful build alone is not treated as proof that your change survived — the tool compares the re-exported result against what was requested and reports the difference.

Verified by the SDKSource never overwritten

Live — read it, and approve the three that change it

With a route saved in your project, AryaAI reads the controller mode, a single tag, or a bounded sweep of up to sixteen tags. The sweep reports achieved timing rather than the interval you asked for, because each read is a sequential call and a requested rate is not a guaranteed one.

Uploading the controller into a new local file, changing its mode, and downloading are the only three actions that change a controller. A download is reachable only from a build verified in the same session, with the controller already in Program mode, and it does not change the mode back.

Built into the application

The ladder, drawn beside the conversation

An .l5x opens as a project, not a wall of XML. The editor panel draws the rungs from the export’s own logic, and every value on screen is labelled as coming from the saved file rather than from a controller.

The Controller Organizer

The tree you already know: controller and its tag count, tasks with their rate and type, scheduled programs and their routines, unscheduled programs, I/O configuration with catalog numbers and slots, add-on instructions, and data types. Search filters the whole tree.

Sections an export does not carry — the fault handler, motion groups, the alarm manager — are shown greyed and marked as not included, rather than quietly missing.

Drawn rungs, not text

Ladder comes back as real contact and coil geometry: XIC and XIO with the negation slash, OTL/OTU/OTE, function-block cards with labelled operands, right-aligned outputs, and rung comments centred above the rail. Structured Text renders as source.

A rung the parser cannot read falls back to its source text instead of guessing. Long routines load the first eighty rungs and offer more.

Evidence on hover, and on right-click

Hovering an operand shows its scope, type, exported value and description. Right-clicking an instruction offers Explain this instruction, Open called routine, Cross References, Add to offline watch, and Ask Arya to change offline file.

The Ask Arya actions only draft a prompt into the composer. You decide whether to send it.

The viewer is offline, and it says so A blue OFFLINE chip sits in the header, and the source bar reads out the file version and the Studio export revision. The watch and the inspector both state that the values shown are the saved export values and not the current controller state. A live feed is the agent’s tool calls, not this panel.

An .acd is not opened here A binary Studio 5000 project shows export guidance and an Ask Arya to prepare an L5X button instead of a tree. The button drafts a request that says, in the prompt itself, not to overwrite the ACD, connect online, download, or modify controller state.

Where stepping back is recorded

What the approval prompt actually names

An approval that says “allow this?” is not worth much. The prompt names the machine and the bytes, and it covers one operation.

Waiting for approval The conversation is taken over by the request: the controller IP you supplied, the route resolved from your own project’s saved FactoryTalk Linx path, the ACD path and its SHA-256, and the exact target mode or change list. Reject is Esc; Allow once is Enter.

  • The tool accepts one outcome only: allowed once. A rejection, a blanket “approved”, or anything unrecognised is denied.
  • There is no approved field in any tool schema, so the model cannot authorize its own action.
  • If the approval service is missing or unreachable, the tool refuses. It fails closed.
  • The route is read from the project you name, and its final IP hop must match the IP you gave. A mismatch stops the call with an explicit error rather than guessing a driver path.

One session setting can make these unavailable Arya’s Full access preset sets the approval policy to never, and under it these three tools cannot request their approval at all. The plugin tells you so and names the fix — switch the session to a preset that asks — rather than searching your installation to work around it. Being able to request is not approval; the human still answers each call.

Stated plainly

What the Logix tools do not do

An agent that overstates what it can reach is dangerous in a plant. These are the boundaries the plugin itself publishes.

Published boundaries
Area The limit
Controller writes No online edit, force, bit toggle, tag write or runtime data change, by any route. A human request cannot authorize one.
Download Written and gated, but never exercised on real hardware. Upload and mode change have been.
Protected logic Encoded add-on-instruction payloads can be re-encoded by the SDK on export, so their equivalence is unverified. That state blocks download eligibility by design rather than passing quietly.
Revisions Observed on 19.01, 33, 34, 36.00 and 37.00–37.02. Opening needs 31 or later; an SDK build needs 37 or later. Anything else is a target, not a verified release.
Languages Ladder and Structured Text are read closely. Function-block diagrams and sequential function charts are structurally read but only partly analysed; alarm data is metadata only.
ACD editing One existing ladder or Structured Text routine at a time, unchanged in type. New routines, tag changes, type changes, multi-routine edits and safety or protected targets are refused.
The checks Static findings are heuristics, not certification. No findings does not prove a program is safe, and a clean build is not a commissioning result.
The plugin itself These guards live in the plugin. An agent given unrestricted shell access, a generic Rockwell SDK client, or Studio 5000 automation could go around them. A deployment that needs the boundary must withhold those.

A milestone is finished when the limit is written down Not when the feature demos. That is why the download gap above is on this page rather than in a changelog.
